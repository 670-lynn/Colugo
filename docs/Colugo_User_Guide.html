Overview

Colugo is a Grasshopper plugin for Rhino that automates LEED compliance calculations using Honeybee / Ladybug energy simulation data. Each component reads simulation outputs (SQL, CSV, or Excel), performs credit-specific analysis, and generates LEED-ready documentation.

Category Component Description
LEED EA EA_Grid Harmonization Grid Harmonization (Case 1/2/3) scoring with battery & load management
LEED EA EA_Renewable Energy Renewable Energy (Eq.1-5) scoring with on-site PV, off-site, EACs & carbon offsets

Installation

  1. 將 Colugo.gha、System.Data.SQLite.dll 及 x64/SQLite.Interop.dll 複製到 Grasshopper Libraries 資料夾：
    %APPDATA%\Grasshopper\Libraries\Colugo\
  2. 重新啟動 Rhino & Grasshopper。
  3. 在 Ribbon 的 Colugo 分頁即可找到所有元件。
Note: 若使用 Debug 模式編譯，Post-build 會自動部署到 Libraries 資料夾。

尖峰負載最佳化 Peak Load Optimization（非電池卸載策略）

代表在需量反應 (DR) 事件期間，你能「關掉」多少設備來減少用電。
這不是改變建築作息，而是緊急時「忍耐一下少用一點」。

#NameTypeDefault說明 Description
6_shedList<Number> Optional 尖峰時段每小時可卸載的 kW 數，支援 1 / 24 / 8760 筆
Load reduction (kW) per hour during on-peak
什麼是「卸載」？
就是電力公司通知你「電網快過載了，請減少用電」時，你的應急計畫能關掉多少 kW：
卸載行動估算方式典型節省
關掉走廊 / 停車場照明照明總功率 × 關閉比例5-30 kW
空調溫度從 24°C 調高到 26°C約降低冷房負載 10-15%10-50 kW
關掉飲水機 / 自販機每台約 0.5-1 kW2-5 kW
停止部分電梯運行每台電梯 ~15-30 kW15-30 kW
關掉非必要排風機風機額定功率5-20 kW
需要卸載多少？ 查看 RecBESS 輸出，裡面會告訴你精確的最低卸載 kW 數。
例如你的建築尖峰 55.8 kW，RecBESS 顯示「卸載 ≥ 5.6 kW」， 那只要關掉幾台飲水機就夠了。
How much to shed? Check the RecBESS output for the exact minimum kW needed.

彈性營運情境 Flexible Operating Scenarios

代表你「重新設計建築的營運排程」後，負載曲線變成什麼樣子。
例如：原本下午 2 點全力開空調，改成早上 10 點就預冷，下午關主機。負載沒有消失，只是搬到別的時間去了。

#NameTypeDefault說明 Description
7_proposedList<Number> Optional 調整排程後的逐時電力需求 kW（8760 值）
Proposed demand after schedule modification
如何產生？ 在 Honeybee 中建立第二個模擬方案（修改空調/設備排程），取得 8760 負載數據接入此處。
多數專案不需要此輸入。 電池 + 卸載 或 電池 + 韌性計劃 就能拿滿 2 分，不必跑兩次模擬。
只有當其他策略都不足以拿分時，才需要動用 Flexible Operating。

模擬電池在離峰充電、尖峰放電的行為。充電會增加離峰時段的電網負載，放電會削減尖峰時段的電網負載。

計分邏輯 Scoring Logic

學分架構 Credit Structure（上限 2 分）

Case 1 (DR Program Enrolled)  = 2 pts   ┐ mutually exclusive
Case 2 (DR Capable)           = 1 pt    ┘
                                          AND / OR
Case 3 (Load Flexibility)    = 1-2 pts   (4 sub-strategies, each 1pt, cap 2)

Total = min(2, max(Case1, Case2) + Case3)

Case 3 四項子策略（每項 1 分，上限 2 分）

策略 Strategy資料來源 Data Source通過條件 Pass Criteria分數
尖峰負載最佳化
Peak Load Optimization		 _shed 卸載排程 卸載後尖峰 ≤ 基準 × 90% 1
現場儲能
On-site Storage		 電池參數 電池放電後尖峰 ≤ 基準 × 90% 1
彈性營運情境
Flexible Operating		 _proposed 新排程 ≥10% 尖峰負載移動 ≥2 小時 1
電網韌性技術
Grid Resilience		 _resil 布林值 電力公司有韌性計劃即可 1
禁止雙重計分 No Double-dipping：每項策略使用獨立的資料來源。 電池放電只能算「現場儲能」；卸載只能算「尖峰負載最佳化」。同一個削減動作不能同時計入多項策略。 
case3_points = min(2,
    peak_opt_point      // from shed schedule
  + storage_point       // from battery simulation
  + flexible_point      // from proposed vs baseline comparison
  + resilience_point    // from user boolean
)

常見問題 FAQ

Q: SQL 讀不到數據？SQL reads no data?

確認 Honeybee 模擬時 HB Simulation Control 有啟用 Facility Total Electricity Demand Rate 輸出。 同時確認 SQL 檔案路徑正確且模擬已成功完成。

Q: 基準負載看起來太低？Baseline load seems too low?

若使用 Ideal Air Loads，請檢查 COP 值。冷氣 COP 設太高會低估電力需求。 可嘗試 _copC = 2.5 做較保守的估算。

Q: Secondary Peak Warning = True？

電池在離峰充電產生了比原始尖峰更高的負載。 解法：降低 _chgKw（充電功率）讓充電更慢更平均。

Q: Flexible Operating 一直 FAIL？

確認：(1) _proposed 有 8760 筆值；(2) 尖峰時段的 proposed 確實比 baseline 少了 ≥10%； (3) 增加的離峰負載出現在距尖峰 ≥2 小時的時段。
多數專案不需要 Flexible Operating。可用電池 + 卸載或電池 + 韌性計劃拿滿 2 分。

Q: 電池容量該設多大？How to estimate battery capacity?

最簡單的方式：直接看 RecBESS 輸出，元件會自動用二分搜尋法計算最低容量。
粗估公式：電池 kWh ≥ 尖峰需求 × 10% × on-peak 小時數 ÷ 放電效率
例如：500 kW 尖峰, 5 小時 on-peak → 500 × 0.1 × 5 ÷ 0.9 ≈ 278 kWh

Q: 可以不用電池嗎？Can I use this without a battery?

可以。設 _battKwh = 0，使用卸載（_shed）+ 韌性計劃（_resil）= 2 分。 甚至不需要任何模擬以外的數據。

Q: _shed 怎麼接最方便？需要卸載多少？

先看 RecBESS 輸出，它會告訴你精確的最低卸載量。
例如顯示「卸載 ≥ 5.6 kW」，那就用一個 Number Slider [6] 接到 _shed 就行了。
5.6 kW 約等於關掉幾台飲水機或部分走廊照明，對多數建築來說很容易達成。
想要更細緻的控制，可用 Gene Pool（24 genes）做每小時排程。

計分邏輯 Scoring Logic

核心概念

計算你的再生能源抵消了多少 % 的建築碳排（CO2e），再對照 Table 1 查得分。
五類策略各自查表，分數可累加，上限 5 分。若 On-site 達 100% 可加 EP。

計算公式 Equations

Eq.1: CO2eT = Σ(EnergySource_i × CO2eCoeff_i)
      建築年度總碳排 = 電力kWh×電力係數 + 天然氣therms×天然氣係數

Eq.2: CO2eR = Σ(RenewableSource_i × CO2eCoeff_i)
      各類再生能源的碳排抵消量（分別計算）

Eq.3: %offset = CO2eR / CO2eT
      物理再生能源的抵消百分比 → 對照 Table 1

Eq.4: %EAC = CO2eR_EAC / (CO2eT - CO2eR_on - CO2eR_new - CO2eR_exist)
      EACs 分母須扣除物理再生能源的貢獻（避免重複計算）

Eq.5: Equivalent = Annual × (ContractYears / 15)
      合約不足 15 年按比例折算

常見問題 FAQ

Q: 碳排係數 (CO2eCoeff) 要用什麼值？

必須與 EA Prerequisite Minimum Energy Performance 使用的係數一致。 通常依區域電網查詢，如 EPA eGRID 或當地電力公司公告值。
台灣電力碳排係數約 0.000502 tCO2e/kWh（2023 年值），天然氣約 0.005302 tCO2e/therm。

Q: On-site PV 產電量看起來不對？

確認 Honeybee 模型有 PV 系統。如果模型沒有 PV，SQL 中不會有產電數據，元件會假設 0。
_sysEff 預設 1.0，若需扣除 DC→AC 轉換損耗可設為 0.85-0.95。

Q: 合約只有 5 年怎麼辦？

輸入 _xxxYrs = 5，元件會自動套用 Equation 5：
Equivalent = Annual × (5/15) = Annual × 0.333
等於只算 1/3 的年購買量。合約越短，折算越多，需要買更多才能拿分。

Q: EACs 的分母為什麼要扣除物理再生能源？

LEED Equation 4 規定，EACs 只能抵消「物理再生能源尚未覆蓋」的碳排。
如果 On-site + Off-site 已經抵消了 50% 碳排，EACs 的分母就是剩下的 50%。
這是為了避免同一筆碳排被重複計算。

Q: 怎麼快速知道 PV 需要多大？

直接看 RecPV 輸出，它會列出 1-5 分 + EP 各需要多少 kWh/yr，
並標示目前已達成或還需增加多少。

Q: 可以不裝 PV 嗎？

可以。完全靠離岸購電和 EACs 也能拿分，最高可到 5 分。
但 Exemplary Performance 只有 On-site 100% 才能獲得。
